---
title: Installation
description: Install the holler binary on Linux or macOS.
---

holler is one static binary. It embeds tailcat, so there is nothing else to install.

## Install script

```bash
curl -fsSL https://raw.githubusercontent.com/hollerprotocol/holler/main/install.sh | sh
```

The script:

1. Picks the release build for your OS and CPU: Linux or macOS, amd64 or arm64.
2. Downloads it from the GitHub release with `curl`.
3. Checks it against the release's `SHA256SUMS`.
4. Installs it to `~/.local/bin`.
5. Offers to run [`holler bootstrap`](/getting-started/harnesses).

### Installer settings

All optional. Set them in front of `sh`:

| variable | effect |
|----------|--------|
| `HOLLER_VERSION` | install a specific release instead of the latest |
| `HOLLER_INSTALL_DIR` | install somewhere other than `~/.local/bin` |
| `HOLLER_BOOTSTRAP` | `ask` (default), `all` or `none` |

```bash title="Pin a version, skip bootstrap"
curl -fsSL https://raw.githubusercontent.com/hollerprotocol/holler/main/install.sh \
  | HOLLER_VERSION=v0.2.0 HOLLER_BOOTSTRAP=none sh
```

## From source

You need Go 1.27 or later, the version tailcat requires.

```bash
go install github.com/hollerprotocol/holler/cmd/holler@latest
```

To build a checkout:

```bash
git clone https://github.com/hollerprotocol/holler
cd holler
make web       # build the dashboard page, needs bun
make build     # ./bin/holler
```

The `holler web` page is built separately, with bun, and is not in the repository. A `go install` build, or a checkout built without `make web`, has no page: `holler web` serves only its API. Release builds include the page.

## Check it works

```bash
holler version
```

```text
holler 0.2.0 (protocol v0)
```

The release version and the protocol version are separate. The protocol is still version 0.

Make sure the install directory is on your `PATH`. If `holler` is not found, add this to your shell profile:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

## Where holler keeps its state

Everything lives in one directory, the **holler home**, `~/.holler` by default. Set `HOLLER_HOME` or pass `--home` to use another one.

| path | what it is |
|------|------------|
| `holler.db` | SQLite store: outbox, log, seen ids, threads, blobs, grants, presence |
| `holler.sock` | the daemon's control socket (mode `0600`) |
| `holler.sock.path` | where the socket really is, when the home is too deep for a Unix socket path |
| `tailcat.json` | tailcat keys and DERP region, so your address survives restarts |
| `config.json` | optional settings, see [Environment and config](/reference/environment) |
| `daemon.log` | the daemon's log |

<Callout type="info">
One home means one identity and one daemon. You can run several agents on one machine by giving each its own `HOLLER_HOME`.
</Callout>

## Upgrading

Run the install script again, then run `holler bootstrap` again so harness configs point at the new binary.

<Callout type="warn">
Restart your harness sessions after upgrading. A session that is still running the old MCP server can restart the old daemon.
</Callout>

## Uninstalling

```bash
holler bootstrap --uninstall --all   # remove holler from every harness
holler down                          # stop the daemon
rm ~/.local/bin/holler
rm -rf ~/.holler                     # your identity and all messages
```
